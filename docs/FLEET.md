# Каскад устройств и конструктор

Один процесс может изображать **несколько ONVIF-устройств сразу**: у каждого свой HTTP/ONVIF-порт, RTSP-порт, серийный номер,
MAC, идентичность WS-Discovery, состояние (`data/state_N.json`), каналы, события и PTZ. Всем управляет один файл
`onvif-emulator.conf` и один веб-интерфейс (у каждого устройства свой GUI на своём порту).

## Сценарий «3 устройства × 3 профиля, PTZ у одного, тревога у всех, аналитика у одной»

```bash
onvif-emulator --service --devices 3 --onvif-port 8080-8082 --rtsp-port 554-556 ^
  --streams 3 --source ./clip.mp4 ^
  --rule "kind=tamper,every=30s" --rule "kind=contact,random=5-200s" ^
  --rule "kind=analytics,topic=line,device=2,every=1m" ^
  --device-set 2:channels.1.ptz_enabled=false --device-set 3:channels.1.ptz_enabled=false ^
  --relays 2 --inputs 2
```

* `--devices 3` и диапазоны портов: устройства на 8080/8081/8082 и RTSP 554/555/556. Только диапазон (`--onvif-port 8080-8089`) —
  число устройств берётся из его длины (10). Порты можно перечислять: `--rtsp-port 554,600,700`.
* `--streams 3` — у каждого канала три профиля **full / medium / low**; качество выстраивается автоматически из основного кодировщика
  (medium = ½ разрешения, low = ¼; частота кадров и битрейт снижаются пропорционально). Профили `profile_1`, `profile_1_sub`, `profile_1_third`,
  RTSP-пути `ch1`, `ch1_sub`, `ch1_third`.
* `--source` — одно видео (файл, RTSP, HTTP…) для всех каналов, каждый поток кодируется в своём качестве.
* `--rule` без `device` работает на всех устройствах; `device=2` — только на втором.
* PTZ есть у каждого канала по умолчанию; `--device-set N:channels.K.ptz_enabled=false` убирает PTZ у канала K устройства N
  (`--set channels.K.ptz_enabled=false` — у всех). Устройство без PTZ отвечает `NoPTZProfile`, в профилях нет `PTZConfiguration`.
* `--devices` и `--onvif-port` можно не задавать в консоли, а записать в файл (блок `fleet`), см. ниже.

## Готовая конфигурация из файла

Настроили в консоли или в GUI — **сохраните** (кнопка «Сохранить» / Ctrl+S). Файл `onvif-emulator.conf` записывается со **стандартным именем**:

* при запуске ищется рядом с программой, затем в каталоге, откуда запущена программа, и **подхватывается сам** — достаточно запустить
  exe без ключей и открыть веб-интерфейс: всё уже настроено;
* если файл переименовать, автоподхват не сработает — указывайте его явно: `-c мой-стенд.conf`;
* `--no-conf` — не читать и не создавать стандартный файл;
* `--export-config FILE` — записать **полную** конфигурацию (каскад, правила, каналы) и выйти; расширение выбирает формат (`.conf`, `.yaml`, `.json`);
* GUI: «Каскад» → «Экспорт всей конфигурации» / «Импорт конфигурации» (Ctrl+E / Ctrl+I); импорт в каскаде сохраняется в файл и применяется после перезапуска.

Сохранение без потерь (проверено тестом `load → save → load`): каналы, профили, PTZ, порты, правила, реле, каскад, лимиты.

## Как правки устройства попадают в файл

Устройство 1 — это **шаблон**: то, что вы меняете в его GUI, меняет общий файл, и остальные устройства это наследуют.
Правки в GUI устройства N ≥ 2 записываются в его блок переопределений `fleet.devices[N-2]` (только отличия от шаблона).
Правило, созданное в GUI устройства 2, принадлежит только ему (`device: 2`); созданное в GUI устройства 1 можно сделать общим (`device: 0`).

```yaml
fleet:
  count: 3
  onvif_ports: 8080-8082
  rtsp_ports: 554-556
  devices:                      # переопределения устройств 2, 3, …
    - device: {model: CAM-2}
      channels_patch: {"1": {ptz_enabled: false}}
diag:
  rules:
    - {kind: tamper, schedule: interval, interval: 30, unit: seconds, device: 0}     # у всех
    - {kind: analytics, topic: line, schedule: interval, interval: 1, unit: minutes, device: 2}
```

## Каналы: свой RTSP-порт, PTZ, события

* `channels[].rtsp_port` — поток канала на своём порту (для него запускается отдельный MediaMTX без HLS/WebRTC).
* `channels[].ptz_enabled` и `channels[].ptz` (свои пределы и скорости) — PTZ на канале или нет.
* События привязаны к каналу (`channel` в правиле), у каждого канала свой источник `vsc_N`, свой симулятор объектов и свой оверлей.
* GUI → Каналы → «Конструктор каналов»: PTZ, свой порт RTSP и число профилей по каждому каналу.

## Что уникально у каждого устройства

Порты, серийный номер (`…-N`), hardware id, hostname, имя, MAC (`02:42:AC:11:xx`), endpoint UUID Discovery, файл состояния, конфиг MediaMTX
(со своим набором портов RTP/RTCP/WebRTC-UDP, чтобы экземпляры не конфликтовали). Адрес в ответах ONVIF берётся из заголовка `Host`, то есть
клиент получает адрес, по которому он реально достучался.

Ресурсы каскада ограничивает [LIMITS.md](LIMITS.md): 10 устройств × 3 профиля — это 30 потоков, поэтому на слабой машине включится ограничение.
