# Troubleshooting

## Камера не находится (Discovery)

- `onvif-emulator doctor` — строка WS-Discovery UDP 3702.
- Файрвол Windows: разрешите Python/exe входящий UDP 3702 и исходящий.
- Две программы не могут слушать 3702 одновременно.
- `--no-discovery` отключает ответ — не используйте это в ODM Discover.
- Добавьте устройство вручную по XAddr.

## ODM: ошибка времени / «device time differs»

GetSystemDateAndTime отдаёт UTC и Local. Укажите IANA `device.timezone` (например `Europe/Moscow`). POSIX TZ в ответе — снимок текущего смещения, DST учитывается через `zoneinfo`.

## 401 Not Authorized

Режим `--auth` должен совпадать с тем, что выбран в ODM. Digest требует nonce с сервера (не кэшируйте старый Authorization). GetSystemDateAndTime специально без пароля.

## RTSP 404 / connection refused

Сначала `GET /health`: `"mediamtx": true` — RTSP-сервер жив; `false` — причина в `"mediamtx_error"` (она же в журнале
уровня CRITICAL и красной строкой на странице «Подключение» / `/info`). Типичная причина — **RTSP-порт занят**:

* процессом MediaMTX или FFmpeg от прошлого запуска, который завершили аварийно (диспетчер задач, `Stop-Process`, падение).
  С 1.5 такие остатки этой же установки (конфиг из той же папки `data/`, эмулятор-родитель уже не существует) и «осиротевшие»
  FFmpeg, публикующие в наш порт, убираются автоматически при старте — в журнале строка `left over from an earlier run`;
* другой программой (чужой MediaMTX, VLC-сервер, другой эмулятор) — её не трогаем, в сообщении имя и PID: закройте её
  или запустите с другим `--rtsp-port`.

Сами дочерние процессы с 1.5 привязаны к эмулятору (Windows Job Object, в Linux `PR_SET_PDEATHSIG`): как бы эмулятор ни
завершился, FFmpeg и MediaMTX завершаются вместе с ним и порт не остаётся занятым.

Иначе — MediaMTX не запущен или другой порт. В URI путь = `channels[].rtsp_path` (`ch1`). В Docker RTSP слушает контейнер `mediamtx`, а эмулятор публикует на него — сеть compose должна резолвить хост.

## Чёрный кадр / OSD нет

OSD — фильтр FFmpeg `drawtext`. Без транскода (`transcode: false` + copy) overlay не вставить: включите `transcode: true` или источник `testsrc`.

## Утечка памяти / 24/7

Пайплайн перезапускается с full-jitter backoff. Подписки PullPoint GC по TTL, очередь ≤128 сообщений, replay-cache Digest/WSSE ограничен LRU. State пишется атомарно раз в 2 с при dirty.

## Падение / нет логов / окно сразу закрывается

При двойном щелке по exe Windows часто стартует из `C:\Windows\System32` или `.venv\Scripts`. Туда лог не пишется.

1. Запускайте из **cmd/PowerShell**, не закрывая окно: `onvif-emulator --service`
2. В первой строке будет `Log file: ...` — откройте этот файл.
3. Если рядом с программой писать нельзя, лог в `%APPDATA%\onvif-emulator\onvif-emulator.log`
4. Сообщение *MediaMTX is not running* — это **не фатал**. GUI и ONVIF работают; нет только RTSP. Положите `mediamtx.exe` в PATH или `vendor\win64`.
5. При ошибке после двойного щелчка консоль ждёт Enter, чтобы текст было видно.

## ODM: не открывается поток / не видны профили

1. Профили и URI берутся из `GetProfiles` / `GetStreamUri`. Адрес в них — тот, по которому ODM обратился к эмулятору (заголовок `Host`);
   если ODM стоит на другой машине, а в URI виден чужой адрес (VPN/виртуальный адаптер), задайте `--public-host <IP>`.
2. Порт RTSP (по умолчанию 8554, у каждого устройства/канала свой) должен быть открыт в файрволе Windows.
3. Без пароля RTSP отвечает 401 — как у настоящих камер. ODM подставляет логин/пароль профиля; они те же, что у ONVIF. Оператор/наблюдатель, ограниченный каналами, получает 401 на чужих каналах.
   RTSP принимает Basic и Digest, транспорты TCP и UDP.
4. Проверка независимо от ODM: `ffprobe -rtsp_transport tcp rtsp://admin:admin@IP:8554/ch1`.
5. Профили full/medium/low: `ch1`, `ch1_sub`, `ch1_third`. Если low/medium пропали и на видео `LOAD SHED` — сработал губернатор, см. [LIMITS.md](LIMITS.md).
6. Проверка протокола строгим клиентом (порядок XML-элементов, как у ODM): `OnvifCamEmuGo/reference/tools/onvif_client_probe.py` (локальная папка, в репозиторий не входит).

## Вход в веб-интерфейс

* «Слишком много попыток» — 5 неверных паролей с одного адреса за 5 минут, подождите минуту.
* После смены пароля, роли или каналов учётки её сеансы закрываются — войдите снова.
* «Недостаточно прав» — раздел или действие только для администратора (см. [USERS.md](USERS.md)).
* Забыли пароль admin — удалите его строку `password` в `data/users.json` и перезапустите (или `--reset-admin`).

## ODM: «Web page» показывает ошибку скрипта

Пункт ODM «Web page» открывает устройство во встроенном Internet Explorer, который не выполняет современный JavaScript веб-GUI.
Начиная с 1.5 эмулятор узнаёт IE и отдаёт ему упрощённую страницу без скриптов (адреса ONVIF/RTSP, профили, авторизация);
в любом браузере она открывается по `/info`. Настраивать эмулятор — в Chrome / Edge / Firefox по `http://IP:порт/`.

## Компьютер тормозит / вентиляторы на максимум

Слишком много устройств/потоков. `onvif-emulator --check-config` покажет оценку (`load: …`). Режим `--limits clamp` (по умолчанию) сам уменьшает
конфигурацию, а губернатор сбрасывает потоки на лету. Подробности и настройки — [LIMITS.md](LIMITS.md).

## Кнопка «Загрузить» ничего не делает / ролик не играет

С 1.6 результат виден прямо в карточке канала (прогресс, «Загружено…», красная ошибка). Частые причины раньше: не выбран файл;
имя с запятой, `&`, `+`, `#`, апострофом (теперь такие символы заменяются на `_`); формат вне списка (список расширен до всего,
что читает FFmpeg). Файл без видеодорожки отклоняется. Если файл уже лежит на компьютере эмулятора — не загружайте его,
укажите путь (вариант 2). Кодек и решение «без перекодирования / перекодировать» пишутся в журнал уровня INFO (`-v`).

## OSD: не видно времени / картинки, время «не то»

Время и дата — часы и часовой пояс компьютера эмулятора (не поле «Часовой пояс» устройства). Картинка показывается, только если
файл существует на компьютере эмулятора (путь проверяется при каждом запуске потока) и включён флажок «Показывать».
Изменения OSD применяются кнопкой «Сохранить» (потоки перезапускаются). На Linux для шрифтов нужен fontconfig (шрифты Sans/Monospace).

## Канал «пропал» через некоторое время

Проверьте `/health` → `pipeline_state`: `ended` — ролик без цикла закончился («Запустить канал заново» или включите цикл);
`outage` — идёт имитация обрыва связи из раздела «Помехи». Помехи выключаются там же («Сбросить»).

## Два эмулятора на одном компьютере: у второго нет видео

Кроме RTSP-порта MediaMTX занимает API (9997), HLS (8888), WebRTC (8889) и UDP 8000/8001/8189. С 1.6 занятые порты второй
экземпляр переносит на свободные (`/health` → `mediamtx_ports`), а если MediaMTX всё же не стартовал — его собственное сообщение
(например `listen udp :8000: bind: ...`) попадает в `mediamtx_error` и журнал. Конфиг MediaMTX у каждого RTSP-порта свой:
`data/mediamtx_<порт>.yml`, поэтому два экземпляра из одной папки больше не переписывают друг другу настройки.

## Порт занят / «сделана попытка доступа к сокету методом, запрещенным правами доступа» (exit 2)

Errno 13 / WinError 10013 на порту 8080 — порт занят другой программой **или зарезервирован Windows** (Hyper-V, WSL, Docker Desktop резервируют диапазоны; проверка: `netsh interface ipv4 show excludedportrange protocol=tcp`).

- Другой порт: `--onvif-port 18080` (и `--rtsp-port 18554`).
- Автоматически: `--auto-port` — берётся следующий свободный (до 50 попыток), новый адрес печатается и открывается в браузере. GUI-exe включает это сам (`--no-auto-port` отключает).
- Сменить порт можно и в работающем веб-GUI: Система → порт → Сохранить.
- `doctor` показывает занятость.

## GUI-exe не открылся / нет окна

У `*-gui.exe` нет консоли. Ошибка запуска показывается окном с причиной; подробности — `onvif-emulator-crash.log` и `onvif-emulator.log` рядом с exe. Из cmd/PowerShell вывод идёт в ту консоль; для отладки удобнее консольная сборка `*-win64.exe` с теми же ключами и `-v`.
