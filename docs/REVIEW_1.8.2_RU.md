# Проверка надёжности — 1.8.2, 30.09.2026

## Исправления

- HTTP API ограничен по размеру запроса; загрузка видеоролика идёт потоком с настраиваемым пределом `limits.max_upload_mb`. Неполный файл удаляется при превышении лимита, отмене или ошибке записи.
- OSD-сообщения событий получили отдельную настройку позиции (9 вариантов), независимо от позиции PTZ HUD. Общая шина ONVIF событий передаёт на видео стандартные тревоги/сброс, события аналитики и метаданные, переключения реле и сухих контактов, а также пользовательские темы. Сообщения локализуются согласно системному `language`; добавлен встроенный кириллический пиксельный шрифт без системных зависимостей.
- В Docker Compose контейнер называется `OnvifCamEmu`. Локальный Docker Desktop smoke deployment использует указанный каталог `V:\TestZone\OnvifEmu\video` с записью, чтобы работали загрузка и список файлов.
- Подготовлено подробное двуязычное описание для Docker Hub: [DOCKERHUB.md](DOCKERHUB.md).

## Проверки

- `pytest`: 235 тестов; отдельно проверены ограничение загрузки, удаление частичного файла, стандартные события event bus, тревоги, счётчики и метаданные аналитики, кириллический рендер и размещение бейджей.
- `ruff check src tests packaging`, `compileall`, `node --check` для GUI-скриптов: успешно.
- Windows console и GUI EXE: HTTP, GUI assets, SOAP, JPEG snapshot, H.264 RTSP 320×240, штатное завершение и освобождение порта проверены через `scripts/release_smoke.py`.
- Linux ELF `--help` и runtime `/health` проверены в Linux-контейнере для предыдущей сборки `1.8.2`; повторная пересборка после последних изменений заблокирована отказом доступа к Docker CLI.
- Docker Compose пересобрал и пересоздал `OnvifCamEmu` версии `1.8.2`; в этой среде последующая проверка health и запись в подключённый каталог через Docker CLI также получила отказ доступа.

## Релизные артефакты

- `dist/onvif-emulator-v1.8.2-win64.exe`
- `dist/onvif-emulator-v1.8.2-win64-gui.exe`
- Linux ELF и архив присутствуют в `dist`, но требуют пересборки после последних изменений.

До проверки владельцем Docker Hub и GitHub публикация не выполнялась. WS-Discovery multicast через Docker Desktop зависит от сети хоста; при недоступности multicast устройство добавляется по адресу ONVIF вручную.
