# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## ONVIF Camera Emulator с PTZ, Restreamer и множителем потоков

**Версия документа:** 1.0
**Дата:** 2026-09-09
**Целевая платформа тестирования:** ONVIF Device Manager (ODM)
**Платформа исполнения:** Linux (Docker), опционально Windows

---

## 1. Общие сведения

### 1.1. Назначение
Программный эмулятор IP-камеры, полностью соответствующий спецификации ONVIF Profile S (базово) с элементами Profiles T/G. Эмулятор:
- отвечает на ONVIF-запросы (SOAP/HTTP) как реальная камера;
- воспроизводит видео из файла или рестримит любой источник (RTSP, HTTP, HLS, файл — как VLC);
- поддерживает все функции PTZ с обратной связью позиции;
- отображает графические OSD-элементы (иконки PTZ, статус) поверх видеопотока;
- генерирует события ONVIF (движение, тамперинг, аналитика);
- формирует множество независимых видеоканалов-потоков на разных RTSP-путях/портах;
- настраивается через графический веб-интерфейс.

### 1.2. Ключевые требования к совместимости
- Обнаружение и работа в ODM без ошибок и предупреждений о несовместимости.
- Корректные XML-namespaces и WSDL-структуры ONVIF 2.x.
- Аутентификация: HTTP Digest, HTTP Basic, WS-Security UsernameToken, режим без аутентификации (выбор в настройках).

## 2. Функциональные требования

### 2.1. Обнаружение (Discovery / WS-Discovery) — обязательно
- Ответ на multicast-запросы Probe на адресе `239.255.255.250:3702` (UDP).
- Отправка ProbeMatch с scopes: `onvif://www.onvif.org/Profile/Streaming`, `onvif://www.onvif.org/hardware/EMU-CAM-1`, `onvif://www.onvif.org/name/<имя>`, `onvif://www.onvif.org/location/<локация>`.
- Scopes настраиваются в GUI.

### 2.2. Сервис Device
- GetSystemDateAndTime / SetSystemDateAndTime (LocalDateTime + TimeZone + UTC offset; DST учитывается).
- GetDeviceInformation: Manufacturer, Model, FirmwareVersion, SerialNumber, HardwareId — задаются в GUI.
- GetCapabilities (все поддерживаемые сервисы и их XAddr).
- GetScopes / SetScopes.
- GetHostname / SetHostname.
- GetNetworkProtocols / SetNetworkProtocols (HTTP, RTSP порты).
- NTP: GetNTP / SetNTP.
- GetUsers / CreateUsers / DeleteUsers / SetUser — роли Administrator/Operator/Viewer, свои учётные данные.
- System: Reboot, сообщения о поддерживаемых версиях ONVIF.

### 2.3. Аутентификация
- Режимы (переключаются в GUI, применяются ко всем сервисам и RTSP):
  1. HTTP Digest;
  2. HTTP Basic;
  3. WS-Security UsernameToken (PasswordDigest);
  4. Без аутентификации.
- Проверка валидности пользователя и на RTSP-потоках (логин/пароль ONVIF = логин/пароль RTSP).
- Настраиваемые логин/пароль (по умолчанию admin/admin), смена пароля через SetUser.

### 2.4. Сервис Media (Profile S)
- GetProfiles — каждый «канал-умножитель» = отдельный ONVIF-профиль.
- GetVideoSources / GetVideoSourceConfigurations / GetVideoEncoderConfigurations (H.264/H.265/MJPEG, разрешение, FPS, битрейт, GOP — значения задаются в GUI).
- GetStreamUri — возвращает RTSP URI вида `rtsp://<host>:<port>/<channel_N>` (MediaMTX path).
- GetSnapshotUri — JPEG-снимок текущего кадра канала (grab из пайплайна).
- GetAudioSources — опционально (заглушка или реальный звук источника).
- Мультикаст-вариант GetStreamUri — опционально.

### 2.5. PTZ-сервис (полный набор)
- GetNodes / GetNode — описание виртуального PTZ-узла (диапазоны pan/tilt/zoom, скорости, поддерживаемые команды: Absolute, Relative, Continuous).
- AbsoluteMove / RelativeMove / ContinuousMove с указанием скорости.
- Stop (PanTilt + Zoom, адресно).
- GetStatus — возвращает ТЕКУЩУЮ виртуальную позицию (pan/tilt в градусах, zoom 0..1), которая плавно меняется фоновым «сервоприводом» эмулятора.
- Presets: GetPresets / SetPreset / RemovePreset / GotoPreset (хранятся в JSON, persistent).
- GetPresetTours / SetPresetTours — туры по пресетам (опционально).
- Автодвижение (AutoMove) и Flip (включить/выключить) — опционально.
- Ограничения (limits) по углам и зуму настраиваются в GUI.

### 2.6. Imaging-сервис
- GetImagingSettings / SetImagingSettings / GetOptions: Brightness, Contrast, ColorSaturation, Sharpness, BacklightCompensation, WhiteBalance (auto/manual), Exposure (iris диафрагма: значение/авто), Focus (auto/manual, near/far).
- Текущие значения и их эффект: диафрагма и фокус — виртуальные параметры состояния; яркость/контраст — применяются к видеопайплайну (эффект реальный).

### 2.7. OSD поверх видео
- Графические элементы, рисуются поверх кадров потока (в пайплайне FFmpeg/GStreamer):
  - стрелки движения: вверх, вниз, влево, вправо, стоп;
  - зум: «+» / «−»;
  - диафрагма (iris): «+» / «−»;
  - фокус: «+» / «−»;
  - иконки событий: движение, тампер, аналитика;
  - текстовый статус: позиция PTZ, имя канала, время.
- Элементы отображаются, пока активна соответствующая команда/событие (время показа настраивается).
- Стилизация (цвет, прозрачность, размер, позиция) настраивается в GUI.

### 2.8. Сервис Events (тревоги и события)
- CreatePullPointSubscription, WS-PullPoint PullMessages, Renew, Unsubscribe, SetSynchronizationPoint, GetEventProperties.
- Поддерживаемые топики (tns1 namespace):
  - `tns1:VideoSource/MotionAlarm` (State, true/false);
  - `tns1:VideoSource/Tampering` (State);
  - `tns1:RuleEngine/FieldDetector/ObjectsInside` (через Analytics-модуль);
  - `tns1:Device/Trigger/DigitalInput` (опционально).
- Режимы генерации событий (настраиваются в GUI): по таймеру (случайно/периодически), по реальному детектору движения на кадрах (опционально), ручной триггер из GUI (кнопка «вызвать тревогу»).
- ODM Event Viewer должен показывать события с корректными timestamp (UTC + offset).

### 2.9. Сервис Analytics (метаданные)
- GetVideoAnalyticsConfigurations, GetAnalyticsModuleOptions, GetAnalyticsModules, GetRules, GetRuleOptions.
- Модули: детектор движения, детектор пересечения линии, детектор вторжения в область (FieldDetector).
- Метаданные кадра (ONVIF AnalyticsStream): список объектов с BoundingBox (left/top/right/bottom — в координатах кадра), класс (Person/Vehicle/Animal/Unknown), confidence, id трека.
- Источник метаданных: имитатор (случайные/сценарные bounding box) или подключение внешней аналитики/детектора.

### 2.10. Restreamer (источники видео)
- Типы источников (как в VLC):
  1. Локальный файл (mp4, mkv, avi, ts и др.) — зацикленное воспроизведение;
  2. RTSP/RTSPS;
  3. HTTP/HTTPS ( progressive, HLS, DASH);
  4. UDP/RTP-мультикаст;
  5. Экран/устройство (опционально, Linux: v4l2/x11grab).
- Параметры источника на канал: URI/путь, буферизация, транскодирование (копировать поток / перекодировать в H.264+H.265+MJPEG для профилей).
- Переподключение при обрыве (автоматически, с экспоненциальной задержкой).

### 2.11. Множитель каналов (stream multiplier)
- Настраиваемое количество каналов N (1..64), каждый канал:
  - свой источник (или общий источник);
  - свой ONVIF-профиль (Media/PTZ/Imaging/Analytics);
  - свой RTSP-путь/порт (MediaMTX: `rtsp://host:8554/ch1`, `...:8555/ch2` и т.д., или один порт — разные пути);
  - возможность включить/выключить канал без перезапуска всего эмулятора;
  - возможность «зацепить» один эмулятор несколько раз (несколько экземпляров или listen-порты).

### 2.12. Графический интерфейс (веб-GUI)
- Встроенный веб-интерфейс на порту эмулятора (или отдельном):
  - Мастер первичной настройки (пользователь, порты, каналы).
  - Меню: Device (информация, время, сеть, NTP), Users, Channels (источники, профили, кодирование), PTZ (limits, скорости, пресеты), Imaging, OSD (стили, элементы, время показа), Events (топики, режимы, ручной триггер), Analytics (модули, сценарии метаданных), Security (режим аутентификации), System (логи, reboot).
  - Предпросмотр живого потока канала (встроенный видеоплеер HLS/WebRTC через MediaMTX).
  - Экспорт/импорт конфигурации (JSON/YAML).

### 2.13. Логирование и диагностика
- Логи: ONVIF-запросы (метод, пользователь, результат), работа пайплайнов, события. Уровни debug/info/warn/error.
- Endpoint диагностики: `/health` для Docker.

## 3. Нефункциональные требования

- Контейнеризация: Docker + docker-compose (эмулятор + MediaMTX).
- Конфигурация: файл (YAML/JSON) + GUI; изменения применяются без рестарта, где возможно.
- Производительность: до 8 каналов 1080p H.264 — на типовом ПК (без перекодирования — remux).
- Стабильность: 24/7, автоперезапуск упавших пайплайнов.
- Локализация GUI: русский + английский.
- Код: Python 3.11+, asyncio, покрытие ONVIX-сервисов; пайплайны — FFmpeg (приоритет) или GStreamer.

## 4. Состав поставки

- Исходный код + Dockerfile + docker-compose.yml.
- Файл конфигурации по умолчанию.
- Документация: README (запуск), MATRIX_ODM.md (чек-лист тестирования в ODM).

## 5. Критерии приёмки

1. ODM: камера обнаруживается через Discovery, подключается во всех 4 режимах аутентификации.
2. ODM: видео обоих (main/sub) потоков профиля проигрывается; snapshot отображается.
3. ODM: PTZ-панель — все движения работают, позиция обновляется, пресеты сохраняются/вызываются.
4. ODM: Event Viewer получает события движения/тампера с корректным временем.
5. OSD: при движении/зуме/событиях на видео видны соответствующие иконки.
6. Множитель: созданные в GUI каналы видны как отдельные ONVIF-профили и RTSP-потоки.
7. Analytics: метаданные с BoundingBox доступны через Analytics-сервис.
8. Все настройки из п.2.12 работают без правки конфиг-файла вручную.

## 6. Поставка и сборка (дополнение к разделу 4)

### 6.1. Портативная сборка Windows
- Обязательная сборка в **один портативный .exe** (PyInstaller, one-file mode, встроенный Python).
- .exe работает без установки, без прав администратора (порты >1024), хранит конфиг рядом с exe или в `%APPDATA%\onvif-emulator\` (выбор при первом запуске).
- Версионирование: имя файла вида `onvif-emulator-vX.Y.Z-win64.exe`; встроенный `--version`.
- В сборку вшиты: FFmpeg-бинарники (или авто-скачивание при первом запуске с кэшем), MediaMTX (embedded или внешний бинарник в подпапке), стартовый конфиг по умолчанию.

### 6.2. Linux-сборка
- Бинарник/скрипты для Linux:
  - `bin/onvif-emulator` — запускатель (shell-скрипт-обёртка);
  - `install.sh` — установка в `/opt/onvif-emulator` + systemd-unit (опционально);
  - `uninstall.sh` — полное удаление;
  - `run.sh` — запуск из распакованного архива без установки.
- ShellCheck-чистые скрипты, `set -euo pipefail`, права на исполнение выставляются автоматически.

### 6.3. Скрипт очистки проекта
- `clean.sh` / `clean.ps1` / команда `make clean` — удаление мусора из дерева исходников:
  - `__pycache__/`, `*.pyc`, `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`;
  - `build/`, `dist/`, `*.spec`, `*.egg-info/`;
  - `.venv/`, логи, временные файлы конфигов, скачанные FFmpeg/MediaMTX артефакты;
  - dry-run режим (`clean.sh --dry-run`) с выводом списка того, что будет удалено.

### 6.4. CI-сборки
- GitHub Actions / GitLab CI: автоматическая сборка exe (Windows) и tar.gz (Linux) при теге релиза; артефакты прикрепляются к релизу.

## 7. Консольная версия (CLI)

### 7.1. Принцип
GUI — опция, а не требование. Все функции программы доступны из консоли: каждый параметр GUI имеет CLI-эквивалент.

### 7.2. Источники конфигурации (приоритет от высшего к низшему)
1. Аргументы командной строки;
2. Указанный файл конфигурации (`-c/--config path.yml`);
3. Конфиг по умолчанию (встроенный / рядом с exe);
4. Переменные окружения с префиксом `ONVIF_EMU_*` (опционально, для Docker).

### 7.3. Ключи командной строки (примеры)
- `--host`, `--onvif-port` (по умолчанию 8080), `--discovery` / `--no-discovery`;
- `--auth {digest,basic,wsse,none}`, `--user`, `--password`;
- `--channels N`, `--channel N:source=<uri>,encoder=...` — декларативное описание каналов;
- `--ptz-pan-limit`, `--ptz-tilt-limit`, `--ptz-zoom-limit`, скорости;
- `--events {timer,motion,manual}`, `--event-motion-interval`, `--event-tamper-interval`;
- `--osd {on,off}`, `--osd-style <preset>`;
- `--device-manufacturer`, `--device-model`, `--device-firmware`, `--device-serial`, `--scopes "..."`;
- `--snapshot {on,off}`, `--rtsp-port` (MediaMTX);
- `--gui` / `--no-gui` / `--headless` (по умолчанию GUI, если есть дисплей);
- `--log-level`, `--log-file`;
- `--check-config` — валидация конфига и выход;
- `--version`, `--help` (полный, с примерами).

### 7.4. Режимы запуска
- `onvif-emulator --help` — подробный хелп: все ключи, значения по умолчанию, примеры команд (минимум 5 типовых сценариев: «1 канал из файла», «рестрим RTSP», «8 каналов», «без авторизации», «headless на сервере»).
- `onvif-emulator doctor` — диагностика окружения: порты свободны, FFmpeg/MediaMTX найдены, multicast-доступность, права.
- Ошибки в аргументах: понятное сообщение + подсказка `См. --help`, коды выхода (0 — ок, 1 — ошибка конфига, 2 — занят порт и т.д.).
- В консольном режиме живой лог в stdout/stderr + необязательный `--log-file`.

## 9. Расширение 1.3: диагностическое устройство, каскад, ресурсы (дополнение к ТЗ)

Цель: эмулятор должен **реально заменять любое ONVIF-устройство** при проверке клиентов (основной клиент приёмки — ONVIF Device Manager 2.2.250)
и служить полноценным диагностическим стендом. Подробности реализации: `docs/DIAGNOSTICS.md`, `docs/FLEET.md`, `docs/LIMITS.md`.

### 9.1. Совместимость с ODM (протокол)
- Порядок XML-элементов ответов — строго по схемам ONVIF (проверка строгим клиентом: zeep `strict=True` по официальным WSDL; ноль ошибок).
- SOAP-ошибки — Fault SOAP 1.2 с HTTP 500 и подкодами `ter:*`; неизвестная операция — `ActionNotSupported`.
- Полный набор Media-операций Profile S/T (опции кодировщика, метаданные, аналитика, аудио-заглушки, `GetServiceCapabilities`), PTZ (`GetConfigurationOptions`, home, capabilities), Imaging (options и move options в порядке схемы), Device (реле, DNS, ZeroConfig, системные вызовы).
- `GetEventProperties`: `TopicSet` с `MessageDescription` на каждый топик; WS-BaseNotification `Subscribe`/`Notify`.
- Адрес в XAddr и RTSP URI — тот, по которому клиент реально обратился (заголовок `Host`), если `public_host` не задан.
- RTSP: Basic и Digest, транспорты TCP/UDP, у каждого экземпляра MediaMTX свои сокеты; источники кодируются в реальном времени.

### 9.2. Многоканальность и профили
- До трёх профилей на канал: `full`, `medium`, `low`; автоматическая лесенка качества из основного кодировщика (`streams: 1..3`).
- У канала свои: источник видео, события, PTZ (включён/выключен, свои пределы), RTSP-порт (отдельный MediaMTX).
- Одно видео на несколько каналов и профилей — `--source`.

### 9.3. Каскад устройств
- N устройств в одном процессе; диапазоны портов ONVIF и RTSP (`8080-8089`, `554-563`); индивидуальные переопределения.
- Уникальные серийный номер, MAC, Discovery UUID, состояние, конфигурация MediaMTX на устройство.
- Правки в GUI устройства сохраняются обратно в общий файл.

### 9.4. Диагностический движок событий
- Любое событие вручную и по таймеру: постоянный интервал или случайный в диапазоне; единицы — секунды, минуты, часы; повторы, стартовая задержка.
- Типы: движение, тампер, аналитика (поле, линия, ячейки), реле, сухой контакт, метаданные, произвольный топик с любыми данными и шаблонами значений.
- Добавление и удаление правил в GUI, REST и консоли (`--rule`); у каждого правила свои настройки и таймер.
- Реле (Bistable/Monostable) и сухие контакты — настоящие сущности ONVIF (`GetRelayOutputs`, `SetRelayOutputState`, события Relay/DigitalInput).
- Доставка: PullPoint, WS-Notify, webhook, поток метаданных, живой журнал.

### 9.5. Оверлей поверх видео
- Живой слой: стрелки PTZ и STOP, ZOOM ±, IRIS ±, FOCUS ± при командах; бейджи событий; рамки объектов метаданных; светодиоды реле и контактов; индикатор сброса нагрузки.
- Рисуется встроенными средствами (без шрифтов и графических библиотек), подаётся в FFmpeg вторым входом.

### 9.6. Защита ресурсов
- Оценка нагрузки до старта; лимиты устройств/каналов/потоков/правил/событий; режимы `off|warn|clamp|strict`.
- Автосброс low/medium-потоков при перегрузе CPU/RAM и возврат при спокойствии; пониженный приоритет FFmpeg/MediaMTX; ограничение частоты событий.

### 9.7. Конфигурация и запуск
- Стандартный файл `onvif-emulator.conf` подхватывается из каталога программы / запуска; сохранение под тем же именем; иное имя — только через `-c`.
- Экспорт/импорт полной конфигурации (`--export-config`, GUI); сохранение без потерь.
- Все возможности управляются ключами консоли; оба exe (консольный и оконный) принимают одинаковые ключи.

### 9.8. Критерии приёмки расширения
1. Строгая проверка протокола без ошибок для Device, Media, PTZ, Imaging, Events.
2. Сценарий «3 устройства × 3 профиля, PTZ у одного, тампер у всех, сухой контакт у всех, аналитика у одной» запускается одной командой и работает.
3. Правила с таймером «1–100 минут» / «5–200 секунд» срабатывают в заданных диапазонах; правила добавляются и удаляются на лету.
4. При PTZ-командах на видео подсвечиваются соответствующие кнопки; события, метаданные и реле видны на видео.
5. Перегруженная конфигурация не «вешает» ПК: уменьшается (clamp) или отклоняется (strict), в работе включается сброс потоков.
6. ODM 2.2.250: Discover, профили, живое видео каждого профиля, PTZ-панель, Event Viewer, реле.

### 9.9. Планируемое
- Версия на Go (лёгкий один бинарник): заготовка в `prep-go-fork/`.
- Media2 (H.265-профили), RTSP-трек метаданных, HTTPS.

## 12. Расширение 1.6: источник видео — загрузка или локальный файл, любые форматы, два эмулятора на одном ПК (дополнение к ТЗ)

Повод: кнопка «Загрузить» внешне не реагировала (ошибки уходили в скрытый журнал, имена с `,&+#'` отклонялись, часть форматов

  прогресс и результат видны в карточке канала; недопустимые символы имени заменяются на `_`; существующий файл не перезаписывается

- **Локальный файл**: полный путь на компьютере, где запущен эмулятор (или выбор через «Обзор» — список дисков/папок/видеофайлов

### 12.2. Форматы и кодеки
- Принимается всё, что читает FFmpeg: MP4, M4V, MOV, MKV, WebM, AVI, WMV, FLV, MPEG/MPG, VOB, TS/M2TS/MTS, 3GP, OGV, MXF и др.
- ffprobe определяет кодек: совпадающий с профилем (H.264 / H.265) отдаётся без перекодирования, остальное (MPEG-2, Xvid/DivX,
  WMV, VP9, ProRes…) перекодируется в H.264 — клиенту всегда приходит обещанный кодек. Файл без видеодорожки отклоняется.

### 12.3. Несколько эмуляторов на одном компьютере
- Служебные порты MediaMTX (API, HLS, WebRTC, RTP/RTCP, WebRTC-UDP) при занятости переносятся на свободные (по таблице сокетов ОС);
  переносы — в журнале и `/health` (`mediamtx_ports`), фактический HLS-порт — на странице «Подключение».
- Конфиг MediaMTX — отдельный на каждый RTSP-порт (`data/mediamtx_<порт>.yml`).
- Вывод MediaMTX перехватывается: причина отказа попадает в `mediamtx_error` и журнал уровня CRITICAL.

### 12.4. Критерии приёмки расширения
1. Загрузка файла с «неудобным» именем (кириллица, запятая, `#`) проходит, прогресс и итог видны без открытия журнала.
2. Путь к локальному файлу (или выбор через «Обзор») включает его на канале без копирования.
3. MPG (MPEG-2), AVI (Xvid), WMV, FLV, MKV (HEVC) приходят в RTSP как H.264; MOV/MP4 с H.264 — без перекодирования.
4. Второй экземпляр на том же ПК с другими портами ONVIF/RTSP получает `"mediamtx": true`.

## 13. Расширение 1.7: OSD (время, дата, картинка), ролик без цикла, имитатор помех (дополнение к ТЗ)

### 13.1. OSD
- Штампы времени и даты — отдельно, каждый: вкл/выкл, формат (strftime + свой текст), положение (9 точек или свои X/Y в %),

### 13.2. Ролик без цикла
- По умолчанию цикл. Без цикла по окончании: остановить поток / застыть на последнем кадре / чёрный экран;
  состояние `ended` в `/health`, кнопка и `POST /api/channels/<id>/restart`.

### 13.3. Имитатор помех (на канал)
- Погода/оптика: дождь (размытие, смаз, контраст, кайма, шум), шум матрицы, пикселизация.
- Вандализм: тряска, закрытие объектива (чёрный / размыт / баллончик) — вспышками или постоянно, с событием Tampering.
- Сеть/поток: потеря пакетов, пропуск кадров, замирания, CBR / VBR со скачками, потолок битрейта, обрывы связи со случайным
  интервалом и длительностью (поток пропадает и возвращается, без счётчика ошибок).
- GUI с пресетами, `--impair`, `PUT /api/channels/<id>/impair` (перезапуск только этого канала).

### 13.4. Критерии приёмки
1. Время и дата с заданными форматом, положением, цветом и прозрачным фоном видны во всех профилях.
2. Логотип (PNG и JPEG с прозрачным цветом) в заданном месте и размере.
3. Ролик без цикла ведёт себя по выбранному действию; «Запустить заново» проигрывает снова.
4. Каждая помеха видна в потоке; при тряске/закрытии приходит Tampering true → false; обрыв связи восстанавливается сам.
